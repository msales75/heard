# Notes

Short rationale for choices that aren't obvious from the code.

- **The engine is created in the FastAPI lifespan, not at import time.** It lives on
  `app.state.engine` and is disposed on shutdown. Importing `heard.main` therefore needs
  no `DATABASE_URL`, and each test gets a fresh engine on its own event loop. An
  asyncpg pool shared across loops fails in confusing ways.
- **The test runs the lifespan by hand** (`app.router.lifespan_context`) because httpx's
  `ASGITransport` doesn't send lifespan events. This avoids an extra dependency
  (`asgi-lifespan`).
- **`python -m heard` (the `heard` script) starts uvicorn with `log_config=None`.**
  By default uvicorn installs its own text handlers. Turning that off lets the
  `uvicorn.*` loggers propagate to the root JSON handler, so all output is one JSON object
  per line. Running `uvicorn heard.main:create_app --factory` directly works, but its logs
  won't be JSON.
- **The logging module is `heard/log.py`, not `heard/logging.py`,** to avoid confusion with
  the stdlib module. Fields passed with `extra={...}` are added to the JSON object.
- **`DATABASE_URL` is required and has no default,** so a misconfigured deploy can't
  quietly connect to a dev database. Copy `.env.example` to `.env` for local work. Real
  environment variables override `.env`.
- **Alembic reads the URL from `heard.config`, not `alembic.ini`,** so there's one source of
  truth and no ConfigParser `%` escaping of passwords. `alembic.ini` still holds Alembic's
  own settings.
- **The migration template was modernized** (`X | None`, `collections.abc`). A ruff
  post-write hook in `alembic.ini` formats new revisions. `F401` is ignored under
  `migrations/versions/` because the template imports `op`/`sa` for hand-written
  migrations.
- **The metadata naming convention** in `heard/db.py` gives constraints deterministic names,
  so autogenerated migrations don't depend on Postgres's default naming. This is much
  harder to add once tables exist.
- **The container runs `alembic upgrade head` before starting the app.** This is fine for a
  single replica. With several replicas, run migrations as a separate one-off job.
- **mypy strict covers `src/` only**, as requested. The pydantic mypy plugin is enabled so
  `Settings()` type-checks without passing required fields.
- **CI runs `alembic upgrade head`** against the service container before pytest. The
  health test doesn't need a schema, but this step checks that the migration chain applies.
